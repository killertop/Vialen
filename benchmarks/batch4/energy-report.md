# 能耗报告：未完成可信能量对照

**本轮没有取得可归因的 Vialen 能量读数，也没有优化前后能耗对照。不得输出省电百分比。**

| 证据类别 | 实际取得 | 可解释范围 |
|---|---|---|
| 硬件电源轨/ODPM | 5 秒能力 trace 出现 8 条轨、每条 6 个样本，均固定 0 | 无有效变化，视为当前采集不可用，不视为零功耗；未将重叠轨相加 |
| 电池电荷 | 6 个样本固定 6,738,000 µAh | 短窗口无可分辨变化；不能当作能量 mWh |
| 电池净电流/电压 | 0～6,000 µA，4,448,000 µV | 外部供电、满电条件下的电池净量，不能直接归因应用或整机输入功率 |
| 软件估算 | 本轮未采集 | 未清全局 batterystats，也未把 CPU、GC 或 Binder 计数包装成能耗 |

[Perfetto power counters](https://perfetto.dev/docs/data-sources/battery-counters) 提供的轨计数属于设备/子系统，不是应用专属能量。当前系统报告 AC 供电且 ADB 为 USB 数据链路；两者都可能影响休眠行为。未模拟电池状态、控制充电、写 sysfs、root、切换网络或调用有充电副作用的 PowerMetric。

能力预检期间实际记录了 CPU 调度和显示帧，而轨仍全零，不能据数据源名称声称 ODPM 可用。仍应在设备恢复后用已发生工作的窗口再核对轨的有效性、分辨率和覆盖范围；若仍无有效计数，需要可靠外部供电测量设备或其他满足条件的硬件。仅物理断开 USB 并不能自动使当前计量可信。

没有完成服务空闲、固定有效业务量、前台统计、订阅失败恢复的多个成对能量窗口；未测真实无线网络或 Android VPN 耗电，也未用同机 loopback 代替。设备断连阻塞后续窗口，原有真实功耗与深睡待机未验证项全部保留。
