## 构建

历史源码通过 git archive 在仓库外独立展开，主工作区不 reset。每份源码独立重建 AAR，使用锁定 Go 1.27.1、JDK 25、NDK 28.1.13356709 和生产 feature tags。共享上游只能是同一已核对的源码输入，不共享 AAR。记录上游 Git 状态/差异哈希、测量叠加文件哈希以及 APK/AAR SHA256。

同一 com.vialen.app.benchmark 包名顺序替换；测试专用签名，不读取正式签名。benchmark 从 Release 初始化，R8/资源压缩开启、debuggable=false、profileable shell=true、arm64。隔离包使用固定测量 versionCode 以支持顺序替换，生产版本不改。测量入口、SQL 计数、原生观察点仅在仓库外测量源码叠加；不修改 main 生产算法，正式 Release 不含这些入口。

固定 ART 为 `cmd package compile -f -m speed`（Full 等效），不生成候选专用 Baseline Profile。每次安装均重新编译并回读结果；预热与正式迭代分开。系统约束、充电、显示、Wi-Fi 和生产 VPN 不修改。

## 工作负载及完成边界

合成配置使用固定整数序列（seed=413），节点名称/域名/端口由索引确定；输入内容摘要记录在每轮结果。预检 100 节点，仅核对工具不纳入正式比较。正式 1,000/10,000 节点。节点类型/排序/显示窗口/脚本相同。

列表加载从测量入口发起实际 MainActivity 导航开始，到目标 RecyclerView 数据与布局可用；不是应用进程冷启动指标。稳定滚动预热一次，正式使用相同像素距离、持续时间和往返次数；刷新修改固定 100 行，计至 adapter 反映修改并完成布局。密集刷新检查实际查询及完成，不计排队为完成。导入计至真实 createProfilesForImport 返回、数据库和选择状态核对，并另计 UI 就绪。

真实 JNI 统计与合成通信计数分别标识。服务/Binder 路径不能由直接 JNI 调用替代；不能把 payload 字节数说成完整 JNI 编码开销。主动 GC 注入和直接调用 Worker 只能作为受控机制窗口，不冒充系统压力/真实后台唤醒。

## 样本、顺序与排除

每个主场景每版本预设至少 10 个有效迭代；两轮预热另计。固定种子 413，成对 AB/BA 交替；先在同一构建做 A/A 检查。轮次是统计单位，帧不是独立样本。保留每轮帧数、P50/P95/P99、截止超时比例、CPU、内存和有效工作量；使用配对差值及固定种子 bootstrap 95% 区间。基线接近零不计算相对比例。

预设排除：系统 thermal status>=2；电池温度>=40℃或配对起始温差>2℃；供电状态改变；工作量/输入摘要不一致；目标不在前台或显示参数改变；超时/采集缺失/帧数据丢失。排除运行保留并标注，不因候选更慢排除。最多两轮固定补采；仍不足 10 则报告样本不足，不无限测到显著。

启动/准备阶段用有限轮询；稳定窗口在设备本地执行，结束后一次读取结果。每个任务有超时，清理仅限专用 benchmark 包与本任务创建的合成组。CPU 需区分主线程、RenderThread、驱动线程、主进程和 :bg；缺失进程不记为 0。RSS/PSS/堆不可直接相加。

## 能耗门槛

当前有外部供电，不用净电池电流归因应用功耗。先验证电源轨是否实际产生有效计数与单位；仅有数据源名称不代表可测。USB/外部供电条件下的窗口不代表日常深睡。软件估算与硬件计数分开，不清 batterystats、不模拟拔电、不使用会改变充电的 PowerMetric 模式。条件不满足时记录阻塞并继续性能，不输出省电百分比。

工具语义参考：[Macrobenchmark](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-overview)、[Perfetto power counters](https://perfetto.dev/docs/data-sources/battery-counters)。本协议在正式比较数据采集前固定；工具预检后的必要修正应保留记录。
